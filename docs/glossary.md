# Glossary

This glossary defines the common terminology used throughout the Cortex project.

Its purpose is to establish a shared language across engineering, product, and AI-related discussions, reducing ambiguity and improving communication.

---

# A

## Adapter

An implementation of a port that integrates Cortex with an external system, such as OpenAI, PostgreSQL, Confluence, or Slack.

Example:

- OpenAI LLM Client
- PostgreSQL Repository
- Confluence Client

---

# C

## Chunk

A smaller fragment of a document created during the ingestion process.

Chunks are the units stored in the vector database and retrieved during semantic search.

A document typically consists of multiple chunks.

---

## Context

The collection of retrieved information provided to the Large Language Model (LLM) to generate an answer.

Context is composed of one or more relevant chunks retrieved from the knowledge base.

---

# D

## Document

A single knowledge source imported into Cortex.

In the MVP, a document corresponds to a Confluence page.

Future versions may support other document types.

Examples:

- Confluence page
- Markdown file
- PDF
- GitHub Wiki page

---

# E

## Embedding

A numerical vector representation of textual content.

Embeddings enable semantic similarity searches instead of traditional keyword matching.

Both documents and user questions are converted into embeddings before comparison.

---

## Entity

A core business object belonging to the domain layer.

Entities encapsulate business rules and possess a unique identity.

Examples:

- Document
- Chunk

---

# H

## Hallucination

A response generated by an LLM that is unsupported, fabricated, or inconsistent with the available evidence.

One of Cortex's primary goals is to minimize hallucinations by grounding responses in retrieved documentation.

---

# I

## Ingestion

The process responsible for importing knowledge into Cortex.

Typical ingestion pipeline:

1. Retrieve documents
2. Extract content
3. Normalize text
4. Split into chunks
5. Generate embeddings
6. Store in the vector database

---

## Indexing

The process of making ingested documents searchable.

Indexing includes generating embeddings and storing them in the vector database.

---

# K

## Knowledge Base

The complete collection of indexed organizational knowledge available to Cortex.

For the MVP, the Knowledge Base consists exclusively of Confluence pages.

---

## Knowledge Source

An external system that contains organizational knowledge.

MVP:

- Confluence

Future examples:

- GitHub
- Jira
- Google Drive
- SharePoint
- Local documents

---

# L

## LLM (Large Language Model)

The AI model responsible for generating responses.

Examples include:

- GPT
- Claude
- Gemini
- Llama

The LLM should never answer using unsupported assumptions when operating within Cortex.

---

# P

## Port

An interface that defines how the application communicates with external systems.

Ports belong to the application layer.

Adapters implement ports.

---

## Prompt

The instruction sent to the LLM.

A prompt typically contains:

- System instructions
- User question
- Retrieved context
- Formatting instructions

---

# R

## RAG (Retrieval-Augmented Generation)

An AI architecture that combines semantic retrieval with text generation.

Instead of relying solely on the model's internal knowledge, relevant documentation is first retrieved and then provided to the LLM as context.

This approach significantly improves answer quality and reduces hallucinations.

---

## Repository

A component responsible for persisting or retrieving domain entities.

Repositories abstract the underlying persistence technology.

---

## Retrieval

The process of searching the vector database to identify the most relevant chunks for a user's question.

Retrieval occurs before answer generation.

---

# S

## Semantic Search

A search technique based on meaning rather than exact keyword matching.

Semantic search uses embeddings to identify conceptually similar content.

---

## Source

The original document used to support a generated answer.

Every Cortex response should reference its sources whenever possible.

---

# U

## Use Case

An application service responsible for orchestrating business operations.

Use cases coordinate domain entities, repositories, and external ports.

Examples:

- AskQuestionUseCase
- ImportConfluenceDocumentsUseCase
- SearchRelevantChunksUseCase

---

# V

## Vector Database

A database capable of storing and searching embeddings efficiently.

The MVP uses PostgreSQL with pgvector.

---

# W

## Workflow

A sequence of operations performed to complete a business process.

Example:

Question

↓

Generate embedding

↓

Retrieve relevant chunks

↓

Build prompt

↓

Generate answer

↓

Return response

---

# Project-Specific Terms

## Cortex

The AI-powered enterprise knowledge assistant developed in this project.

Its objective is to enable employees to discover organizational knowledge through natural language interactions.

---

## MVP

The first functional release of Cortex.

Scope:

- Confluence integration
- Slack integration
- Semantic search
- RAG
- Source citations

---

## Bootstrap

The initial milestone responsible for preparing the project's technical foundation.

Includes:

- Poetry
- FastAPI
- PostgreSQL
- pgvector
- Docker
- Alembic
- Health Check
- Configuration
- Project structure

---

# Guiding Principle

Throughout the project, terminology should remain consistent.

When introducing a new concept, prefer extending this glossary instead of creating alternative names for the same idea.
